## 1. 제품 개요

사용자가 PDF 파일을 웹 페이지에 끌어다 놓으면(드래그&드롭) 서버가 텍스트를 추출하고, AI(OpenRouter 경유 LLM)가 **한 줄 요약 / 핵심 포인트 / 상세 요약** 3단 구성의 한국어 요약을 만들어 보여주는 로컬 실행형 웹 앱이다.

### 1.1 목표
| # | 목표 | 측정 지표 |
|---|------|-----------|
| G1 | 긴 PDF의 핵심을 1분 내외로 파악 | 10페이지 텍스트 PDF 기준 업로드~요약 표시 p50 ≤ 30초 |
| G2 | 설치·사용이 단순 | `uvicorn` 한 줄로 실행, HTML 파일 하나로 사용 |
| G3 | 실패 시 이유를 사용자가 이해 | 모든 실패가 정의된 에러 코드 + 한국어 메시지로 표시 |
| G4 | 비용 최소화 | 저가 유료 DeepSeek 모델 사용(무료 V3.1 모델은 OpenRouter에 없음 — §2 참고), 실패 시 다른 저가 DeepSeek 모델로 폴백 |

### 1.2 대상 사용자
- 보고서·논문·매뉴얼 등 긴 PDF를 빠르게 훑어야 하는 한국어 사용자(학생, 직장인, 연구자).
- 개발자가 아닌 사용자도 브라우저만으로 사용 가능해야 한다(서버 실행은 운영자/본인이 1회 수행).

### 1.3 핵심 사용 시나리오
1. **기본 흐름**: 사용자가 `index_pdf.html`을 연다 → PDF를 드래그&드롭(또는 "파일 선택") → 업로드·텍스트 추출 진행 표시 → 문서 정보(파일명, 페이지 수, 글자 수) 표시 → 요약 진행 표시 → 한 줄 요약/핵심 포인트/상세 요약 표시 → "복사" 또는 "다운로드(.md/.txt)".
2. **스캔 PDF**: 이미지로만 된 PDF 업로드 → "텍스트를 추출할 수 없습니다(스캔 이미지 PDF로 보입니다)" 안내. OCR은 하지 않는다.
3. **암호화 PDF**: 비밀번호 걸린 PDF 업로드 → "암호가 걸린 PDF는 지원하지 않습니다" 안내.
4. **기본 모델 혼잡**: 기본 모델이 429/5xx/60초 초과 → 서버가 자동으로 폴백 모델 사용 → 결과에 실제 사용 모델과 "(대체 모델 사용)"이 표시된다.
5. **서버 미실행**: `file://`로 HTML을 열었으나 서버가 꺼져 있음 → "서버에 연결할 수 없습니다. 백엔드 실행 여부를 확인하세요" 안내.

## 2. 확정 기술 결정 (변경 불가)

| 영역 | 결정 |
|------|------|
| 백엔드 | Python FastAPI + PyMuPDF(`pymupdf`). 실행: 프로젝트 루트에서 `uvicorn backend.main:app --port 8000`. 설치된 Python은 **3.14** (의존성은 3.14 호환 버전 사용) |
| AI | OpenRouter Chat Completions API. 당초 기본 모델은 **DeepSeek V3.1 무료**(`deepseek/deepseek-chat-v3.1:free`)였으나, **2026-10-11 검증 결과 OpenRouter에 DeepSeek V3.1 무료 모델이 존재하지 않아** 사용자 지시("없거나 너무 느리면 다른 적당한 유료모델")에 따라 저가 유료 모델을 쓴다. 코드 기본값: 기본 `deepseek/deepseek-v3.2`, 폴백 `deepseek/deepseek-chat-v3.1`. 환경변수 `OPENROUTER_MODEL`/`OPENROUTER_FALLBACK_MODEL`로 덮어쓸 수 있으며, 현재 운영 `.env`는 `OPENROUTER_MODEL=deepseek/deepseek-chat`을 지정한다(실제 기본 모델은 `/api/health`의 `default_model`로 확인). |
| 비밀값 | 프로젝트 루트 `.env`의 `OPENROUTER_API_KEY`를 `python-dotenv`로 로드. 키는 로그·응답·프론트엔드에 절대 노출하지 않는다 |
| 프론트엔드 | 프로젝트 루트 **단일 파일 `index_pdf.html`** (HTML+CSS+vanilla JS 인라인). 모든 UI 문구 한국어 |
| 프론트 접근 방식 | (a) `file://`로 직접 열기 → `http://localhost:8000` API 호출, (b) FastAPI가 `GET /`에서 같은 파일을 서빙 → 동일 출처 상대경로 호출 |
| 폴더 구조 | `backend/`(FastAPI), `tests/`, `docs/`, 루트에 `index_pdf.html`, `.env`, `requirements.txt` |

> 가정: 에이전트 공통 기준의 "`frontend/` 폴더" 항목은 이번 프로젝트에서 위 확정 결정(루트 단일 파일 `index_pdf.html`)으로 대체한다.

## 3. 기능 요구사항

우선순위: **P0** = MVP 필수, **P1** = MVP에 포함 권장, **P2** = 차기.

| ID | 기능 | 우선순위 | 설명 |
|----|------|----------|------|
| F-01 | PDF 업로드(드래그&드롭) | P0 | 업로드 영역에 PDF를 끌어다 놓으면 업로드 시작. 드래그 중 영역 강조 |
| F-02 | PDF 업로드(파일 선택) | P0 | "파일 선택" 버튼 → `accept=".pdf,application/pdf"` 파일 대화상자 |
| F-03 | 클라이언트 사전 검증 | P0 | 확장자/크기(20MB) 사전 검사 후 서버에서도 재검증 |
| F-04 | 텍스트 추출 | P0 | `POST /api/upload` — PyMuPDF로 전 페이지 텍스트 추출, 메타데이터 반환 |
| F-05 | AI 요약 | P0 | `POST /api/summarize` — 한 줄 요약, 핵심 포인트(3~7개), 상세 요약 생성 (한국어) |
| F-06 | 모델 폴백 | P0 | 기본 모델 실패(429/5xx/60초 초과/네트워크 오류/모델 없음) 시 폴백 모델로 1회 재시도 |
| F-07 | 결과 표시 | P0 | 3단 구성 결과 + 사용 모델 + 소요 시간 표시 |
| F-08 | 진행 상태 표시 | P0 | "업로드 중 → 텍스트 추출 완료 → 요약 중" 단계 및 스피너, 진행 중 중복 업로드 방지 |
| F-09 | 에러 표시 | P0 | 서버 에러 JSON의 `message`(한국어)를 그대로 표시 + 다시 시도 가능 |
| F-10 | 헬스체크 | P0 | `GET /api/health` — 서버 상태, API 키 설정 여부 |
| F-11 | 결과 복사 | P1 | 전체 요약을 Markdown 텍스트로 클립보드 복사, "복사되었습니다" 피드백 |
| F-12 | 결과 다운로드 | P1 | 요약을 `.md` 파일로 다운로드 (`<원본파일명>_요약.md`) |
| F-13 | 긴 문서 청크 요약 | P1 | 일정 길이 초과 시 청크 분할 요약 후 병합 (§6) |
| F-14 | 추출 텍스트 미리보기 | P2 | 추출 텍스트 앞부분 접기/펼치기 미리보기 |
| F-15 | 새 파일 요약 | P0 | "다른 파일 요약하기"로 초기 상태 복귀 |
| F-16 | 서버 연결 상태 표시 | P1 | 페이지 로드 시 `/api/health` 호출, 실패 시 상단 배너로 서버 미실행 안내 |

## 4. 비기능 요구사항

### 4.1 제한값
| 항목 | 값 | 비고 |
|------|----|------|
| 최대 업로드 크기 | **20MB** (20 × 1024 × 1024 = 20,971,520 바이트) | 초과 시 `FILE_TOO_LARGE` (413) |
| 허용 형식 | PDF만 | 확장자 `.pdf`(대소문자 무관) **그리고** 파일 시그니처 `%PDF-` 확인 |
| 최대 페이지 수 | 300페이지 (가정) | 초과 시 `TOO_MANY_PAGES` (413) |
| 요약 입력 최대 길이 | 300,000자 (가정) | 초과 시 `TEXT_TOO_LONG` (413) |
| 요약 입력 최소 길이 | 공백 제거 후 1자 이상 | 비어 있으면 `EMPTY_TEXT` (400) |
| 스캔 PDF 판정 | 추출 텍스트(공백 제거) 합계 < 20자 (가정) | `NO_TEXT` (422) |
| AI 호출 타임아웃 | 모델 호출 1회당 **60초** | 초과 시 폴백 |
| 요약 API 전체 상한 | 180초 (가정) | 초과 시 `AI_TIMEOUT` (504) |

### 4.2 성능 목표
| 시나리오 | 목표 |
|----------|------|
| `/api/upload` (10MB 이하 텍스트 PDF) | p95 ≤ 3초 |
| `/api/health` | p95 ≤ 200ms (외부 호출 없음) |
| `/api/summarize` (≤ 30,000자, 단일 청크) | p50 ≤ 30초, 폴백 포함 최대 120초 |
| `/api/summarize` (청크 분할) | 청크 수에 비례, 상한 180초 |

### 4.3 지원 PDF 유형
| 유형 | 지원 | 처리 |
|------|------|------|
| 텍스트 기반 PDF | O | 정상 추출 |
| 다중 페이지 PDF | O | 페이지 순서대로 추출, 페이지 사이 빈 줄 구분 |
| 한글/영문 혼합 | O | UTF-8 유지, 한글 깨짐 없어야 함 |
| 암호화 PDF(열기 암호) | X | `ENCRYPTED_PDF` (422) |
| 권한 암호만 있는 PDF(열기 가능) | O | PyMuPDF로 열리면 정상 처리 (가정) |
| 스캔 이미지 PDF | X | `NO_TEXT` (422), OCR 미지원 |
| 손상 파일 / 확장자만 .pdf | X | `CORRUPTED_PDF` 또는 `INVALID_FILE_TYPE` |
| 0바이트 파일 | X | `EMPTY_FILE` (400) |

### 4.4 보안·개인정보
- `OPENROUTER_API_KEY`는 서버에서만 사용. 응답·로그·에러 메시지·HTML에 키 값 포함 금지.
- 업로드 파일은 **메모리에서 처리**하고 디스크에 저장하지 않는다(임시 파일 사용 시 처리 직후 삭제).
- 서버는 요약 텍스트를 영구 저장하지 않는다(무상태).
- CORS: `file://` 출처(브라우저가 `Origin: null` 전송)와 `http://localhost:8000`, `http://127.0.0.1:8000`을 허용. 로컬 전용 앱이므로 `allow_origins=["*"]`도 허용(가정). 인증 정보(credentials)는 사용하지 않는다.
- 업로드된 문서 내용이 OpenRouter(외부 서비스)로 전송됨을 UI 하단에 한 줄로 고지한다.

### 4.5 호환성
- 브라우저: 최신 Chrome / Edge / Firefox.
- OS: Windows 11 기준 개발·검증 (경로에 한글 포함됨 — 경로 처리 시 인코딩 문제 없어야 함).

## 5. API 개요

상세 스키마는 `FEATURE_SPEC.md` §3 참조.

| 메서드 | 경로 | 요청 | 성공 응답 |
|--------|------|------|-----------|
| GET | `/` | — | `index_pdf.html` (text/html) |
| GET | `/api/health` | — | `{status, api_key_configured, default_model, fallback_model, version}` |
| POST | `/api/upload` | `multipart/form-data`, 필드 `file` | `{text, metadata{filename, size_bytes, page_count, char_count, title, author}}` |
| POST | `/api/summarize` | JSON `{text, filename?}` | `{summary{one_line, key_points[], detailed}, model, fallback_used, elapsed_ms, chunk_count}` |

에러는 모든 엔드포인트에서 동일 형식:
```json
{ "error": { "code": "NO_TEXT", "message": "PDF에서 텍스트를 추출할 수 없습니다. 스캔된 이미지 PDF는 지원하지 않습니다." } }
```

## 6. 요약 출력 형식과 긴 문서 처리 정책

### 6.1 출력 형식 (기본 출력 언어: 한국어)
| 필드 | 형식 | 규칙 |
|------|------|------|
| `one_line` | 문자열 | 1문장, 100자 이내 권장 |
| `key_points` | 문자열 배열 | 3~7개, 각 항목 1~2문장, 불릿 기호 없이 순수 텍스트 |
| `detailed` | 문자열 | 3~6개 문단, 문단 구분은 `\n\n` |

- 원문이 영어 등 다른 언어여도 **요약은 한국어**로 작성한다(고유명사·전문용어는 원어 병기 허용).
- 모델에는 JSON 형식 출력을 지시하고, 서버가 파싱·검증한다. 파싱 실패 시 1회 재요청, 그래도 실패하면 `AI_INVALID_RESPONSE`(502).

### 6.2 긴 문서 처리 (청크 분할 후 병합)
- 청크 크기: **최대 30,000자** (가정, AI통합 에이전트가 모델 컨텍스트에 맞춰 조정 가능하되 FEATURE_SPEC에 반영).
- 분할 경계: 문단(`\n\n`) → 줄바꿈 → 문장 끝 순으로 가장 가까운 경계에서 분할. 청크 간 겹침 없음.
- 텍스트 ≤ 30,000자: 단일 호출로 최종 요약.
- 텍스트 > 30,000자 (Map-Reduce):
  1. **Map**: 각 청크를 부분 요약(핵심 내용 위주 한국어 요약 텍스트).
  2. **Reduce**: 부분 요약들을 합쳐 최종 3단 JSON 요약 1회 생성.
- 최대 청크 수: 10 (= 300,000자 상한과 일치).
- 응답의 `chunk_count`로 분할 수를 알린다(단일 호출이면 1).
- 폴백 정책은 각 호출 단위로 적용한다. 한 번 폴백이 발생하면 같은 요청의 나머지 호출도 폴백 모델을 사용한다(가정: 지연 누적 방지).

## 7. 에러/엣지 케이스 정의

| 상황 | 감지 위치 | 코드 | HTTP | 처리 |
|------|-----------|------|------|------|
| PDF 아닌 파일(확장자 또는 시그니처 불일치) | 프론트(확장자), 서버(둘 다) | `INVALID_FILE_TYPE` | 400 | 업로드 거부 |
| `file` 필드 누락 | 서버 | `NO_FILE` | 400 | 거부 |
| 0바이트 | 서버 | `EMPTY_FILE` | 400 | 거부 |
| 20MB 초과 | 프론트, 서버 | `FILE_TOO_LARGE` | 413 | 거부 |
| 암호화 PDF | 서버 | `ENCRYPTED_PDF` | 422 | 거부 |
| 손상 PDF (열기 실패) | 서버 | `CORRUPTED_PDF` | 422 | 거부 |
| 300페이지 초과 | 서버 | `TOO_MANY_PAGES` | 413 | 거부 |
| 텍스트 없음(스캔 PDF) | 서버 | `NO_TEXT` | 422 | 거부, OCR 미지원 안내 |
| 요약 요청 본문 형식 오류 | 서버 | `INVALID_REQUEST` | 400 | 거부 |
| 요약 텍스트 비어 있음 | 서버 | `EMPTY_TEXT` | 400 | 거부 |
| 요약 텍스트 300,000자 초과 | 서버 | `TEXT_TOO_LONG` | 413 | 거부 |
| API 키 미설정 | 서버 | `API_KEY_MISSING` | 500 | 운영자 안내 메시지 |
| API 키 무효(401/403) | 서버 | `AI_AUTH_ERROR` | 502 | 폴백하지 않음 |
| 기본+폴백 모두 60초 초과 / 전체 180초 초과 | 서버 | `AI_TIMEOUT` | 504 | 다시 시도 안내 |
| 기본+폴백 모두 429 | 서버 | `AI_RATE_LIMIT` | 429 | 잠시 후 재시도 안내 |
| 크레딧 부족(402) | 서버 | `AI_ERROR` | 502 | 일반 AI 오류 |
| 기본+폴백 모두 5xx/네트워크 오류 | 서버 | `AI_ERROR` | 502 | 다시 시도 안내 |
| 모델 응답 JSON 파싱 실패(재요청 후) | 서버 | `AI_INVALID_RESPONSE` | 502 | 다시 시도 안내 |
| 예상치 못한 서버 예외 | 서버 | `INTERNAL_ERROR` | 500 | 스택트레이스 비노출 |
| 존재하지 않는 경로 | 서버 | `NOT_FOUND` | 404 | — |
| 서버 미실행/네트워크 단절 | 프론트 | (`NETWORK_ERROR`, 프론트 전용) | — | 서버 실행 안내 |

## 8. 수용 기준 (요약)

상세 AC(Given/When/Then, 테스트 ID 포함)는 `FEATURE_SPEC.md` §6에 있다. 릴리스 판정 기준:
1. `FEATURE_SPEC.md`의 P0 AC 전부 통과.
2. 모든 에러 응답이 `{ "error": { "code", "message" } }` 형식이고 `code`가 에러 코드 표에 정의된 값.
3. `OPENROUTER_API_KEY` 값이 어떤 응답·로그·HTML에도 나타나지 않음.
4. `file://` 방식과 `http://localhost:8000/` 방식 모두에서 기본 흐름 성공.
